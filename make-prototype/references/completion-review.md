# 완료 검수

**실제 사용처와 사용자 흐름으로 검수하고, 발견한 범위 내 결함을 고친 뒤 완료한다.**

해당 범위만 확인한다. 미확인 항목을 통과로 표시하거나 mock 성공을 실제 연동 성공으로 보고하지 않는다.

## 구조·디자인

- 책임·사용처로 중복을 검색하고 실제 import와 상태 소유자가 정한 경계에 맞는지 확인한다. 순환 참조·도메인에 의존하는 공용 UI·불필요한 상태 복제를 점검한다.
- 쓰이지 않는 scaffold·임시 구현은 정리하고 사용자의 무관한 코드는 보존한다.
- 실행 화면의 토큰·타이포·아이콘이 기준과 일치하는지 확인한다. 반복 소개문과 그 빈 공간은 제거하되 폼 라벨·접근성 이름·필수 안내는 유지한다.
- 좁고 넓은 화면에서 긴 제목·많거나 빈 데이터의 잘림·overflow를 확인한다. 키보드·포커스·대화상자 닫기와 필요한 상태의 다음 행동을 검증한다.

## 실제 흐름

- 구현한 생성·편집·삭제·검색·필터 흐름을 끝까지 실행해 결과가 관련 화면에 일관되게 반영되는지 확인한다.
- 저장은 약속한 경계를 호출하며 새로고침·뒤로가기와 URL·유지 범위가 일치해야 한다.
- 관련 실패·재시도·중복 제출 방지, console/runtime 오류와 네트워크 요청을 확인한다. mock 실패도 같은 데이터 경계에서 재현한다. 스크린샷만으로 동작 검증을 대신하지 않는다.

## 웹 Storybook

- 탐색 분류가 역할별로 구분되고 각 탭·단계의 필요한 상태를 실제 부모 스토리에서 직접 열 수 있는지 확인한다.
- 기본 탭 외의 직접 URL·새로고침·탭 전환을 확인한다. 부모와 단독 자식이 같은 실제 UI·데이터를 쓰며 레이아웃이 유지되는지 비교한다.
- 로딩·오류가 안정적으로 재현되고 router/store/cache가 스토리 사이에 오염되지 않는지 확인한다.
- 정적 build와 실제 렌더링을 각각 검증한다. 앱의 핵심 흐름도 별도로 실행한다.

## 마감

프로젝트의 lint·타입 검사·build와 관련 테스트를 실행한다. 새 테스트는 업무 규칙·상태 전이·데이터 계약·실제 회귀 위험을 검증할 때 추가한다. 문구·파일 수·구현 자체를 복제하는 테스트는 만들지 않는다.

수정 후 영향받은 검증을 다시 수행한다. 막힌 항목은 원인과 미확인 흐름을 명시하고 완료한 부분과 구분한다.
