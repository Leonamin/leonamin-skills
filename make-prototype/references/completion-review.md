# 완료 검수

파일 수나 폴더 모양 대신 실제 사용처와 사용자 행동을 근거로 검수한다. 아래 항목 중 범위에 해당하는 것만 확인하고, 확인하지 않은 것을 통과로 표시하지 않는다.

## 구조와 중복

- 엔트리와 페이지에 재사용 UI, 업무 규칙, 외부 접근이 다시 몰리지 않았는가?
- 유사한 이름뿐 아니라 같은 책임의 컴포넌트/훅/서비스를 검색하고 사용처를 비교했는가? 기존 A를 두고 A′를 만들지 않았는가?
- 공용 primitives, 공용 조합, 도메인 UI의 경계가 실제 import와 일치하는가? 순환 참조나 공유 영역의 도메인 의존이 없는가?
- 공유 레이아웃과 상태/업무 규칙의 소유자가 일관적인가? 같은 상태의 복제, 불필요한 전역화, 지나친 boolean variant가 없는가?
- 쓰이지 않는 scaffold, 임시 구현과 교체된 컴포넌트를 정리했는가? 사용자가 작성한 무관한 코드를 정리 명목으로 삭제하지 않았는가?

## 디자인과 접근성

- 실제 렌더링에서 토큰과 제목/본문/라벨 위계가 적용되는가? 화면마다 별도의 임의 값으로 같은 역할을 표현하지 않는가?
- 라벨·제목·소개문이 같은 기능을 반복하지 않는가? 불필요한 문구를 없애면 빈 wrapper·예약된 설명 공간도 사라지는가? 폼 라벨·접근성 제목·상태와 필수 안내는 유지되는가?
- 제품 UI에 이모지 아이콘이 없고 선택한 아이콘 세트가 일관되는가?
- 주요 화면을 좁은 화면과 넓은 화면에서 확인했는가? 긴 제목, 많은 데이터, 빈 데이터에서도 overflow·잘림·레이아웃 붕괴가 없는가?
- 포커스가 보이고 키보드로 핵심 동작에 도달하는가? 폼 label, 아이콘 버튼의 이름, 대화상자의 포커스/닫기 동작이 적절한가?
- 필요한 로딩·빈 결과·실패·폼 오류 상태가 사용자가 다음 행동을 알 수 있게 표시되는가?

## 실제 기능

- 요청한 핵심 흐름을 시작부터 끝까지 실행한다. 생성/편집/삭제/검색/필터 중 구현한 동작의 결과가 관련 화면에 일관되게 반영되는지 확인한다.
- 저장 버튼은 약속한 저장 경계를 실제로 호출하는가? 새로고침과 뒤로가기에서도 정해 둔 유지 범위와 URL 의미가 지켜지는가?
- 오류 후 재시도와 중복 제출 방지 등 해당 흐름의 실패 경로를 확인한다. mock이라면 실패도 같은 데이터 경계에서 재현한다.
- 브라우저 console/runtime 오류와 필요한 네트워크 요청을 확인한다. screenshot만으로 클릭·저장·접근성을 검증했다고 하지 않는다.

## 웹 Storybook

- 프리미티브, 공용 레이아웃/패턴, 도메인별 컴포넌트와 화면이 탐색 구조에서 구분되는가?
- 화면·탭·단계별 실제 상태가 부모 화면 스토리로 연결되는가? 자식 단독 스토리만 있고 부모에서 볼 수 없는 상태가 없는가?
- 기본 탭 외의 스토리 URL을 직접 열거나 새로고침해도 해당 프래그먼트가 실제 부모의 header, 탭, container 안에 보이는가?
- 부모 안의 탭/단계 전환도 동작하며 자식 단독 스토리와 동일한 실제 컴포넌트·상태 데이터를 사용하는가?
- 로딩·빈 결과·오류가 원하는 상태로 안정적으로 유지되고 스토리 간 router/store/cache 오염이 없는가?
- Storybook 정적 build와 실제 렌더링을 각각 검증했는가? 정적 build 성공만으로 모든 스토리의 동작을 통과 처리하지 않는다.

## 자동 검증과 마감

기존 프로젝트의 lint, 타입 검사, build 및 변경과 관련된 테스트를 실행한다. 새 테스트는 핵심 업무 규칙, 상태 전이, 데이터 계약 또는 실제 회귀 위험을 검증할 때 추가한다. 문구·파일 수·구현 자체를 복제하는 테스트로 품질을 대신하지 않는다.

검수에서 발견한 범위 내 결함을 수정하고 영향을 받은 검증만 다시 실행한다. 도구·실행 환경이 없어 확인하지 못하면 이유와 확인하지 못한 흐름을 명시한다. 실제 서버 없이 mock으로 통과한 결과와 실연동 결과를 구분한다.
