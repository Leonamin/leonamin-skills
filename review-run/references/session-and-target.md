# 독립 세션과 대상 고정

## 세션 경계

새 세션에는 아래의 검토 패키지만 전달한다. 개발 대화, 그 요약, 작성자의 자기평가나 리뷰 결론을 전달하지 않는다. 개발 세션에서 작성한 사실 설명은 필요하면 코드로 검증할 주장으로 표시한다.

- 프로젝트 위치 또는 접근 가능한 저장소 식별자.
- `review-run` 스킬 위치와 검수 자료 위치.
- 고정된 비교 기준과 대상, 포함/제외 범위.
- 사용자의 원래 요구사항과 승인된 설계/acceptance criteria의 원문 또는 문서 경로.
- 검증 환경과 허용 범위. 이전의 테스트 성공 주장은 새로운 리뷰의 증거로 대신 사용하지 않는다.

최상위 새 세션이 필요하다. 대화 fork나 서브에이전트로 대체하지 않는다. 호스트 도구가 새 세션을 지원하면 해당 도구의 실제 스키마와 권한을 따른다. 새 세션 실행을 지원하지 않으면 사용자가 붙여 넣을 인계문을 만든다. 실행하지 않은 세션 ID나 검토 결과를 만들지 않는다.

이미 독립적으로 시작된 리뷰 세션에서는 다시 세션을 생성하지 않는다. 리뷰 도중 요구사항 확인을 위한 사용자의 답변은 받아도 되지만 개발자의 자기평가로 판정을 대체하지 않는다.

## Git 대상

현재 branch를 바꾸거나 사용자 변경을 stash/reset하지 않는다. 읽기 전용 Git 조회 또는 호스트가 지원하는 분리 checkout으로 대상 코드를 읽는다. branch 이름은 즉시 전체 SHA로 해석하며, 이후 이름이 이동해도 고정 SHA를 검토한다.

| 요청 | 비교 기준 |
|---|---|
| 단일 일반 커밋 C | `C^`와 `C` |
| 루트 커밋 | 저장소 object format에 맞게 계산한 빈 tree와 C |
| merge 커밋 | 사용자가 부모를 지정하지 않으면 first parent 대비로 검토하고 이를 명시 |
| 기준 브랜치 대비 대상 브랜치 | 기준 SHA와 대상 SHA를 고정하고 `git merge-base` 결과부터 대상 SHA까지 |
| 명시적 두 revision 비교 | 지정된 두 revision을 그대로 비교; branch 도입분 비교와 구분 |

기준 브랜치가 없으면 저장소의 확인된 PR base 정책을 사용한다. 확인할 수 없거나 merge-base가 여럿이거나 이력이 부족하면 필요한 비교 기준을 질문하고 그 범위의 판정은 보류한다. `HEAD~1`을 모든 요청의 기준으로 가정하지 않는다. patch뿐 아니라 해당 revision의 전체 파일, import 대상, 호출부를 읽는다.

## 커밋되지 않은 변경

`현재 변경사항`은 기본적으로 HEAD 대비 staged+unstaged와 non-ignored untracked 소스 파일을 포함한다고 알린다. 사용자가 staged만 또는 다른 범위를 지정하면 그것을 따른다. tracked 파일에 비밀값이 있을 수 있으므로 상태에서 범위를 먼저 확인하고 비밀 파일은 내용 수집에서 제외한다. 제외 사실은 기록한다.

새 세션을 시작하기 전에 저장소 밖의 임시 위치에 스냅샷을 만든다.

1. base HEAD와 상태, 포함/제외 경로를 기록한다. staged만이면 index 내용을, 전체 변경이면 working tree 최종 내용을 기준으로 삼는다.
2. 선택한 tracked 변경의 binary-safe patch와 필요한 untracked 파일을 보존한다. `git diff`만으로 untracked가 포함됐다고 가정하지 않는다. staged-only에서 working tree의 unstaged 내용을 섞지 않는다.
3. manifest에 patch/파일 내용 지문과 수집 시각을 기록하고, 수집 전후 입력이 달라졌으면 재수집한다. snapshot ID는 수집 내용의 지문으로 정한다.
4. 새 세션은 고정 base와 스냅샷에서 대상 코드를 재구성해 읽는다. 원래 checkout의 계속 변하는 파일을 대상으로 삼지 않는다. 파일 이동·삭제, symlink, binary 등 재현하지 못한 항목은 검토 공백으로 남긴다.

스냅샷을 안전하게 만들 수 없다면 자동 커밋하지 말고 커밋 SHA 제공 등 필요한 입력을 요청한다. 임시 파일은 보고에서 위치를 명시하며 다른 작업의 임시 자료를 삭제하지 않는다.

## 인계문 예시

```text
$review-run을 사용해 아래 대상을 리뷰해줘. 이 세션은 개발 대화를 상속하지 않는 리뷰 전용 세션이야.
프로젝트: <접근 가능한 위치>
스킬: <review-run/SKILL.md>
검수 자료: <경로 또는 없음>
비교 방식: <커밋 / branch 도입분 / 두 revision / 스냅샷>
기준 SHA: <고정 SHA>
대상 SHA 또는 snapshot ID와 위치: <고정 대상>
요구사항과 승인된 설계: <원문 또는 문서 경로>
범위와 제외 항목: <명시>
코드 수정 없이 근거가 있는 지적, 검토 범위와 검증 공백을 보고해줘.
```

실제 전달 시 빈 placeholder를 남기지 않는다. 요청에 요구사항이 없으면 `제공되지 않음: 설계 의도 적합성은 확인 범위에서 제외`라고 적는다. 새 세션 실행 도구가 있으면 결과를 확인해 완료 여부를 보고하며, 실행 실패나 대기 상태를 완료로 표시하지 않는다.
