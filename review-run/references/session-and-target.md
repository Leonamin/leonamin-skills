# 독립 세션과 대상 고정

**개발 이력 없는 최상위 세션에 고정된 검토 패키지만 전달한다.**

## 전달 패키지

프로젝트·스킬·검수 자료 위치, 고정 기준/대상과 포함/제외 범위, 원래 요구사항·승인 설계/acceptance criteria, 검증 환경·허용 범위를 전달한다. 개발 대화·요약·자기평가·기존 결론은 제외한다. 필요한 사실 설명은 코드로 확인할 주장으로 표시하고 과거 테스트 성공을 새 증거로 대신하지 않는다.

fork·서브에이전트로 대체하지 않는다. 새 세션 도구의 스키마·권한을 따르고 실행 결과를 확인한다. 실패·대기를 완료로 표시하거나 세션 ID·결과를 만들지 않는다. 사용자에게 요구사항을 확인할 수 있지만 자기평가로 판정을 대체하지 않는다.

## Git 대상

branch 변경·stash·reset 없이 읽기 전용 조회나 분리 checkout을 사용한다. 이름은 전체 SHA로 고정하고 patch뿐 아니라 전체 파일·import·호출부를 읽는다.

| 요청 | 기준 |
| --- | --- |
| 일반 커밋 C | `C^`와 `C` |
| 루트 커밋 | 저장소 object format에 맞춘 빈 tree와 C |
| merge 커밋 | 지정 부모 또는 first parent; 사용한 부모 명시 |
| 기준 대비 브랜치 도입분 | 양쪽 SHA 고정 후 merge-base부터 대상까지 |
| 명시적 두 revision | 지정 쌍 그대로 비교 |

기준이 없으면 확인된 PR base 정책을 사용한다. 기준 불명·복수 merge-base·부족한 이력은 필요한 입력을 요청하고 판정을 보류한다. `HEAD~1`을 모든 요청의 기준으로 삼지 않는다.

## 미커밋 스냅샷

현재 변경의 기본 범위는 HEAD 대비 staged+unstaged와 non-ignored untracked 소스다. 지정 범위를 우선하며 상태로 경로를 확인하고 비밀 파일은 수집에서 제외해 보고한다.

1. 저장소 밖 임시 위치에 base HEAD·상태·포함/제외 경로를 기록한다. staged-only는 index, 전체 변경은 working tree 최종 내용을 사용한다.
2. 선택한 tracked 변경의 binary-safe patch와 필요한 untracked를 보존한다. `git diff`만으로 untracked가 포함됐다고 가정하거나 staged-only에 unstaged를 섞지 않는다.
3. manifest에 내용 지문·수집 시각을 기록하고 전후 입력이 바뀌면 재수집한다. snapshot ID는 수집 내용의 지문으로 정한다.
4. 리뷰 세션은 고정 base와 스냅샷으로 재구성한다. 원래 checkout의 변하는 파일은 사용하지 않는다. 이동·삭제·symlink·binary 등 재현하지 못한 항목은 검토 공백으로 남긴다.

안전한 수집이 불가능하면 자동 커밋하지 말고 커밋 SHA 등 입력을 요청한다. 임시 위치를 보고하고 다른 작업의 자료는 삭제하지 않는다.

## 실행할 수 없을 때

사용자가 새 세션에 전달할 인계문에 스킬 호출, 위 패키지와 읽기 전용 검토·출력 요구를 넣는다. 빈 placeholder를 남기지 않는다. 요구사항이 없으면 설계 의도 적합성을 확인 범위에서 제외했다고 명시한다.
