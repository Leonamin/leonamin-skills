# Figma 디자인 구현

**기존 디자인 기준과 라이브러리를 재사용해 편집 가능한 네이티브 화면·컴포넌트를 만든다.**

제품 정체성·IA·토큰을 임의로 재정의하거나 코드 GUI를 수정하지 않는다. 필요한 방향 결정은 `$design-product`, 코드 GUI 감사는 `$design-audit`를 사용한다.

## 진행

1. 대상 화면·컴포넌트·변수 매핑과 주요 행동·콘텐츠 계층을 정한다. DESIGN.md·코드 토큰·브리프·Figma 중 현재 기준을 확인한다. 관련 감사 결과가 있으면 반영하고 결과에 영향을 주는 충돌만 확인한다. 별도 초기화나 감사 실행을 필수로 요구하지 않는다.
2. 연결 도구의 실제 읽기·쓰기 기능과 사용 규칙을 확인하고 기존 파일·페이지·라이브러리·컴포넌트·변수를 검색한다. 기존 구조를 우선하며 필요한 최소 범위만 추가한다.
3. [Figma 레이아웃과 검증](references/figma.md)에 따라 프레임·오토 레이아웃·변수·스타일·컴포넌트·변형으로 구현한다. 토큰을 매핑하고 레이어는 역할로 이름 붙인다. 납작한 화면 이미지로 편집 가능한 산출물을 대신하지 않는다.
4. 실제 결과의 편집성·리사이징·토큰·주요 흐름과 감사 항목 해결 여부를 확인한다. 자유 배치는 최소 예외 프레임에 격리하고 이유와 동작을 검증한다. 라이브러리 인스턴스를 정책에 맞추려고 detach하거나 재구성하지 않는다.

## 도구가 없거나 쓰기가 불가능할 때

계획·페이지/프레임/컴포넌트 구조·토큰 매핑·미해결 감사 항목과 다음 도구 작업을 전달한다. 연결 상태·파일 수정·완료 여부를 확인 없이 주장하지 않는다.

## 완료

참조 근거·범위, 생성·수정한 페이지·프레임·컴포넌트, 토큰·라이브러리 매핑, 편집성·리사이징·레이아웃 예외 검증과 미완료 항목을 보고한다. 별도 결정 기록은 요청받았을 때 기존 문서에 남긴다.
