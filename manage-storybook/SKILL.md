# Storybook 생성·관리

실제 제품 UI를 탐색하고 주요 상태와 동작을 확인할 수 있는 Storybook을 제공한다. 기존 프로젝트의 구성과 실행 도구를 활용한다.

## 접속

- 기본 실행 환경은 로컬과 공유 네트워크에서 접속 가능하다.
- 로컬 주소와 공유 네트워크 주소, 실행·종료 방법을 제공한다.
- 원격 접속은 해당 네트워크에서 도달 가능한 주소를 사용하며, 실제 접속을 확인한 범위를 명시한다.

## 분류

- 공용 UI와 도메인별 화면은 탐색 트리에서 구분된다.
- 공용 UI는 기본 요소와 조합 패턴으로 구분된다.
  - 기본 요소: 버튼·입력·토글처럼 하나의 역할을 수행하는 UI.
  - 조합 패턴: 검색 도구 모음·목록 패널처럼 여러 역할을 묶은 UI.
- 내부 구현의 조합 여부보다 사용자가 다루는 역할과 복잡도로 분류한다. 아이콘 버튼이나 설명이 붙은 토글처럼 단일 역할에 가까운 UI는 기본 요소에 포함한다.
- 도메인별 UI는 도메인 안에서 화면과 하위 컴포넌트를 구분한다. 하위 컴포넌트 스토리만으로 화면 스토리를 대체하지 않는다.

## 상태와 동작

- 각 컴포넌트는 기본 상태와 사용 판단에 필요한 주요 상태를 보여준다. 비활성·로딩·오류·빈 상태 등은 해당하는 경우에 포함한다.
- 조작 가능한 UI는 스토리 안에서도 상태가 바뀐다. 토글 켜기·끄기, 입력값 변경, 선택, 펼치기·닫기 등 핵심 동작을 확인할 수 있다.
- 상태별 스토리와 직접 조작은 서로 보완한다. 모든 조합을 나열하거나 동작 기록만으로 상태 변화를 대신하지 않는다.
- 화면 스토리는 실제 레이아웃과 주요 사용자 흐름을 재현한다.

## 유지와 검증

- 실제 제품 컴포넌트를 사용하고 데이터·인증·외부 요청은 재현 가능한 fixture로 대체한다. 공유 데이터 변경이나 실제 외부 작업이 발생하지 않는다.
- 컴포넌트 변경 시 관련 스토리의 상태·동작·분류도 현재 구현과 일치한다. 기존 story ID와 직접 링크는 가능한 한 유지한다.
- 변경한 스토리의 렌더링과 핵심 인터랙션을 확인한다. fixture로 확인한 UI와 실제 API·권한·저장 검증을 구분해 보고한다.
