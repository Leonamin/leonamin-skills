# Manage DESIGN.md

**확인된 디자인 기준을 DESIGN.md에 기록하고 토큰 참조·문서 형식·변경 일관성을 검증한다.**

기존 DESIGN.md와 코드·Figma의 원본 관계를 먼저 확인한다. 문서 작업을 이유로 기준을 임의 이전하거나 UI 코드를 수정하지 않는다. 읽기 전용 검증 요청에는 파일을 만들거나 바꾸지 않는다.

## 진행

1. 요청 범위와 기존 DESIGN.md를 확인하고 실제 UI·코드·스크린샷·디자인 파일·명시된 브랜드 자료에서 근거를 모은다. 생성 요청에 문서가 없으면 루트에 작성한다.
2. 관찰한 값과 명시된 결정을 구분한다. 미확인 사항은 `Known Gaps`에 남기며 브랜드·수치·접근성 준수·반응형 동작을 추정으로 단정하지 않는다.
3. [형식과 명령](references/google-design-md.md)에 따라 재사용 값은 YAML 토큰으로, 적용 이유·규칙·제약은 본문으로 기록한다. 컴포넌트와 본문은 실제 토큰을 참조하고 필요한 상태 변형만 정의한다.
4. `npx @google/design.md lint DESIGN.md`를 실행해 끊긴 참조를 해결한다. 경고는 수정하거나 의도와 근거를 보고한다. 실행할 수 없으면 원인과 미검증 범위를 남긴다.
5. 이전 버전이 있고 변경이 크면 `npx @google/design.md diff <before> DESIGN.md`로 의도치 않은 삭제·변경을 확인한다.

## 기준과 결과

- DESIGN.md를 원본으로 채택했다면 경쟁 토큰 원본을 만들지 않는다. 구현용 파생 산출물은 필요할 때 export한다.
- 본문 설명에 재사용 값을 숨기거나 관찰 근거가 없는 값을 lint 통과만으로 사실처럼 표현하지 않는다.
- 변경 토큰·컴포넌트, 근거, 검증 결과와 남은 Known Gaps를 보고한다.

제품 정체성·IA를 새로 정해야 하면 `$design-product`를 함께 사용한다.
