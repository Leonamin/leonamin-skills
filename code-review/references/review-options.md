# 요청 시 수행하는 선택 작업

## 리뷰 자료 준비

자료 생성·갱신을 요청받았을 때만 수행한다. 제품 코드·스키마·기존 지침·CI 변경이나 실제 리뷰·PR 게시로 범위를 확대하지 않는다.

- 지정 위치를 우선하고 없으면 `.review-context/`에 `index.md`와 필요한 영역 자료만 작성한다. 특정 프레임워크나 계층을 가정하지 않고 모노레포의 앱 경계를 유지한다.
- index에 조사 범위·제외 범위, 기준 commit과 dirty 여부, 원본 정책·영역 자료 링크, 미조사·충돌 항목을 남긴다. dirty 또는 비Git 자료는 조사한 파일의 내용 지문으로 기준을 구분한다.
- 공용 UI·로직, 에러 경로, 책임·상태, 데이터 소유권 중 필요한 영역을 조사한다. 후보의 원본 경로·symbol, 지원 계약·한계, 대표 호출부·테스트와 확인 상태를 기록한다. 소스 전체를 복제하지 않는다.
- 명시적 정책과 관찰된 관행을 구분하고 기존 중복을 표준으로 삼지 않는다. 미발견은 검색 범위를 남기고, 사용자 설명·결정·예외는 갱신 시 보존한다.
- 비밀값·환경 파일 내용·운영 데이터는 수집하지 않는다. 자동 커밋하거나 ignore 설정을 바꾸지 않는다.

저장 위치·조사 기준·범위·미확인 사항을 보고한다. 자료 준비를 실제 리뷰 완료로 표현하지 않는다.

## 독립 세션 리뷰

사용자가 개발 이력을 전달하지 않는 독립 리뷰를 요청한 경우 적용한다. 이미 그런 세션에서 수행 중이면 다시 생성하지 않는다.

1. 기준·대상을 전체 commit SHA 또는 재현 가능한 스냅샷으로 고정한다. PR·브랜치 도입분은 확인된 base와 merge-base, 명시적 두 revision은 지정 쌍을 사용한다. merge commit은 사용한 부모를 명시한다. 기준이 불명확하면 확인하고 `HEAD~1`을 일괄 적용하지 않는다.
2. 미커밋 변경은 요청 범위를 우선하며 기본은 HEAD 대비 staged·unstaged·무시되지 않은 untracked 소스다. 저장소 밖 임시 위치에 base·포함/제외 경로·binary-safe patch·필요한 untracked·내용 지문을 보존한다. staged-only에 unstaged를 섞지 않는다. 입력이 바뀌면 다시 수집하고 재현하지 못한 항목은 검토 공백으로 남긴다.
3. 새 세션에는 프로젝트·스킬·선택 자료 위치, 고정 기준·대상, 포함/제외 범위, 원래 요구사항·승인 설계, 검증 환경·허용 범위만 전달한다. 개발 대화·요약·자기평가·기존 리뷰 결론을 넘기지 않는다. 과거 테스트 성공을 새 검증 증거로 대신하지 않는다.
4. 호스트의 세션 생성 기능과 사용자 권한을 따른다. 개발 이력을 상속한 fork나 서브에이전트를 독립 세션으로 간주하지 않는다. 원래 checkout을 변경하거나 자동 커밋하지 않는다.
5. 새 세션은 고정 대상과 원본 계약을 읽어 리뷰한다. 결과에 기준·대상·독립 수행 여부와 검증 공백을 명시하며, 검토 후 변경된 코드까지 판정이 유효하다고 보지 않는다.

새 세션을 실행할 수 없으면 완성된 전달문과 `미실행` 상태를 제공한다. 현재 개발 세션의 검토로 독립 리뷰를 대체하거나 대기·실패를 완료로 보고하지 않는다. 리뷰 완료는 병합·배포 승인이 아니다.
