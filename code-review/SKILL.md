# 코드 리뷰

**변경으로 생기는 실제 결함을 찾아 영향과 최소 수정 방향을 보고한다.**

리뷰는 읽기 전용이다. 수정도 요청받았다면 해당 결함을 고치고 관련 검증을 수행한다.

1. diff·호출자·관련 설정과 프로젝트 규칙을 읽어 변경 목적과 영향 범위를 확인한다.
2. 정확성·회귀를 우선하고 필요한 관점만 [검토 기준](references/review-checklist.md)으로 확인한다.
3. 결함과 선택적 개선을 구분하고 같은 원인의 발견 사항을 합친다. 포매팅·린트 결과·취향을 구조적 결함으로 반복 보고하지 않는다.
4. 프로젝트 심각도 체계를 우선하고 없으면 `blocker / major / minor / suggestion`으로 정렬한다. 각 항목에 파일:행·문제·발생 조건·영향·근거·수정 방향을 남긴다.
5. 발견 사항 뒤에 확인 범위와 검증 공백을 짧게 보고한다. 문제가 없으면 없다고 명시한다.
