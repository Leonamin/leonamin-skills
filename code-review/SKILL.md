# 코드 리뷰

1. diff와 주변 호출 코드를 읽고 변경 목적, 영향 범위와 프로젝트 규칙을 확인한다.
2. correctness와 회귀를 우선 확인한다. 이름, 언어 의미, 모듈 경계, 테스트·오류 처리의 세부 점검이 필요하면 [review-checklist.md](references/review-checklist.md)의 관련 항목만 읽는다.
3. 실제 결함과 선택적인 개선을 구분하고 같은 원인의 발견 사항을 합친다. 포매팅·린트 결과나 취향을 구조적 결함으로 반복 보고하지 않는다.
4. 프로젝트의 심각도 체계를 우선하고, 없으면 blocker / major / minor / suggestion으로 정렬한다. 각 항목은 파일:행, 문제, 영향, 근거와 수정 방향을 포함한다.
5. 발견 사항이 없으면 확인 범위와 남은 검증 공백을 짧게 보고한다. 수정도 요청됐다면 발견 사항을 고치고 관련 검증을 수행한다.

별도 에이전트나 고정 역할 구성은 요구하지 않는다. 독립 검토가 필요한지는 작업 범위와 실행 환경에 맞춰 판단한다.
