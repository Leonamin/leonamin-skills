# 시안 작성 형식

HTML/CSS Before·After 시안을 작성할 때만 이 문서를 읽는다.

## 비교 구조

- Before와 After는 기본적으로 상하로 배치해 각 패널이 viewport 가로 폭을 사용하게 한다.
- 비교 wrapper가 실제 화면을 절반으로 축소하지 않게 한다. 행 방향 grid에는 `minmax(0, 1fr)`를 사용한다.
- 두 패널의 데이터, 상태와 가로 기준을 동일하게 유지하고 `BEFORE`, `AFTER`를 명확히 표시한다.
- 필요하면 clean·dirty 같은 상태 변형을 별도 작은 예시로 추가하되 기본 비교 조건을 바꾸지 않는다.

## 제품 UI와 시안 설명

- 실제 화면, 코드 또는 사용자 요청에서 확인한 문자열만 제품 UI 안에 넣는다.
- 제품 UI는 `.ui-surface` 안에 둔다.
- 설명은 `.ui-surface` 밖의 `.sketch-annotation[data-sketch-only="true"]`에 둔다.
- 설명에는 `SKETCH NOTE · NOT FOR IMPLEMENTATION` 라벨을 사용하고 점선 테두리와 `--sketch-*` 색상처럼 제품 UI와 구별되는 표현을 사용한다.
- HTML 주석으로 실제 구현에 복사할 영역과 제거할 시안 전용 영역을 표시한다.

## 시각적 제약

- 확인한 제품 색상, spacing, radius, typography와 공용 primitive를 우선한다.
- CSS gradient, 과도한 shadow, 임의의 장식 이미지와 가짜 브랜드 요소를 추가하지 않는다.
- 외부 CDN, 원격 폰트와 네트워크 이미지에 의존하지 않는다. 필요한 자산은 로컬 상대 경로나 인라인 데이터로 사용한다.
- Before에 없는 기능, 데이터, 배지 또는 안내를 만들어 현재 문제를 약화하지 않는다.
- After에서 바뀐 경계, 밀도, 정보 계층과 액션 상태가 비교 이미지에 드러나게 한다.

## 검증 경계

- viewport 캡처는 실제 화면 높이에서 가림과 도달성을 확인하는 용도다.
- full 캡처는 전체 비교 문서를 공유하는 용도이며 결과 이미지 높이가 viewport보다 길 수 있다.
- 정적 HTML로 표현만 확인한 키보드, 포커스, 로딩과 오류 동작은 실제 구현 검증으로 간주하지 않는다.
