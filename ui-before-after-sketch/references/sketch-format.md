# 시안 작성 형식

**비교 조건을 맞추고 제품 UI와 시안 설명을 분리한다.**

## 비교 조건

- 기본은 상하 배치로 각 패널에 viewport 가로 폭을 제공한다. wrapper 때문에 실제 화면을 절반으로 축소하지 않는다. grid track은 `minmax(0, 1fr)`를 사용한다.
- 데이터·상태·가로 기준·배율·스크롤 위치를 맞추고 `BEFORE`·`AFTER`를 표시한다. Before를 축소·흐리게·저채도로 처리하거나 After에 변경과 무관한 여백 확대·그림자·강조색을 더해 낫게 보이지 않게 한다.
- 이 비교로 판단할 질문 하나를 문서 상단이나 annotation 첫 줄에 둔다. 답할 수 없는 질문이면 범위를 좁힌다.
- After의 경계·밀도·정보 계층·액션 상태 변화가 해결할 문제와 연결되어 보이게 한다.
- 변경이 2개 이상이면 After의 해당 위치에 `.sketch-mark` 번호를 붙이고 annotation의 같은 번호와 대응시킨다. 마커는 `data-sketch-only="true"`이며 구현에서 제거한다.

## 상태 비교

기본은 확인된 현재 상태 하나와 그 After다. 대표 상태는 요청이나 근거가 있을 때만 붙인다.

- 상태 후보는 [상태 선택 기준](../../ui-design-concept/references/states-and-handoff.md)의 표에서 제품에 해당하는 것만 골라 보통 2~3개로 제한한다. 모든 조합을 그리지 않는다.
- Before는 확인된 현재 상태를 유지하고, After에 `AFTER · 값 없음`, `AFTER · 조회 실패`처럼 상태를 라벨에 붙여 같은 문서에 세로로 쌓는다. 전체 캡처 한 장에 모든 상태가 담긴다.
- 상태마다 viewport 폭·데이터 의미·공통 영역을 유지하고 달라지는 영역만 다르게 그린다.
- 값 없음·오류·건수 문구를 지어내지 않는다. 확인된 문자열이 없으면 가정으로 표시하거나 그 상태를 생략한다.
- 상태가 4개 이상이거나 문서가 지나치게 길면 탭으로 묶을 수 있다. 탭은 `.ui-surface` 밖의 시안 전용 컨트롤로 표시하고, 캡처는 상태별로 나눠 전달한다.

## UI와 설명

제품 UI는 `.ui-surface`에 두고 확인된 문자열을 사용한다. 요청된 새 문구는 After의 제안임을 구분한다. 설명은 밖의 `.sketch-annotation[data-sketch-only="true"]`에 두며 `SKETCH NOTE · NOT FOR IMPLEMENTATION`, 점선·`--sketch-*` 색상으로 구분한다. HTML 주석으로 구현 영역과 제거할 시안 영역을 표시한다.

## 표현

- 확인된 제품 색상·간격·radius·타이포·공용 컴포넌트를 우선한다. 장식용 gradient·과도한 그림자·임의 이미지·가짜 브랜드를 추가하지 않는다.
- 외부 CDN·원격 폰트·네트워크 이미지에 의존하지 않는다. 필요한 자산은 로컬 상대 경로나 인라인 데이터로 사용한다.
- 아이콘 자리에는 이모지를 쓰지 않는다. 제품 아이콘 세트를 우선하고 없으면 [아이콘 기준](icons.md)의 인라인 SVG 스프라이트를 쓴다.
- Before에 없는 기능·배지·안내를 만들어 현재 문제를 약화하지 않는다.

## 캡처

`full`은 전체 비교 문서를 공유하는 기본 모드이며 이미지가 viewport보다 길 수 있다. `viewport`는 지정 높이에서 가림·도달성을 확인하는 모드다. 정적 HTML의 키보드·포커스·로딩·오류 표현은 실제 동작 검증이 아니다.
