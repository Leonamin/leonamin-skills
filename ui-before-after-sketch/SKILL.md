# UI Before/After Sketch

실제 제품 코드를 바꾸기 전에 현재 구조와 제안 구조의 차이를 같은 조건에서 비교하는 저비용 시안을 만든다.

## 권한과 경계

- 기본값은 읽기 전용이다. 제품 소스, 데이터, 배포 환경과 디자인 시스템을 수정하지 않는다.
- `Before`는 확인한 구조를 재현하고 `After`는 요청된 개선만 반영한다.
- 시안은 의사결정 자료다. 구현 또는 production 검증 완료로 표현하지 않는다.
- 실제 화면이나 파일에 접근하지 못해 핵심 구조를 확인할 수 없으면 임의로 만들지 않고 필요한 근거를 요청한다.

## 진행

1. 대상 화면, 상태와 viewport를 정한다.
2. 근거를 역할에 맞게 확인한다.
   - 실제 화면·스크린샷: 보이는 구조와 상태
   - 컴포넌트 코드: 동작, 접근성 이름과 상태 전환
   - 디자인 토큰·공용 primitive: 제품 일관성
   - 사용자 설명: 확인되지 않은 부분을 보완하는 명시적 가정
3. 핵심 문제를 1~3개로 압축하고 같은 데이터·상태·viewport로 Before와 After를 설계한다. 데이터 의미, 권한과 주요 동작은 요청 없이 바꾸지 않는다.
4. 시안 작성 전에 [references/sketch-format.md](references/sketch-format.md)를 읽는다.
5. 플랫폼이 제공한 시각화 디렉터리를 사용한다. 없으면 `mktemp -d`로 저장소 밖에 만들고 최종 응답에 절대 경로를 남긴다.
6. `<skill-dir>/assets/minimal-sketch/`를 작업별 시각화 디렉터리에 복사해 실제 근거로 교체한다. 제품 고유 구조 때문에 템플릿이 방해되면 새 HTML/CSS를 작성해도 된다.
7. `agent-browser --version`을 확인한 뒤 렌더링한다.

   ```bash
   <skill-dir>/scripts/capture_html_screenshot.sh \
     <index.html> <output.png> [width] [height] [full|viewport]
   ```

   `full`은 전체 비교 문서를 캡처하는 기본 모드다. `viewport`는 지정된 화면 높이에 실제로 보이는 영역만 캡처한다. 반응형 문제가 범위에 있으면 데스크톱과 모바일을 각각 렌더링한다.
8. 생성된 이미지를 직접 확인하고 잘림, overflow, 텍스트 겹침과 비교 불균형을 수정한 뒤 다시 캡처한다.

`agent-browser`가 없거나 캡처에 실패하면 원인을 명시하고 PNG를 검증되지 않은 방식으로 대체하지 않는다.

## 완료 결과

1. Before/After PNG
2. 바뀐 구조 2~4개와 해결하려는 문제
3. HTML/CSS 절대 경로
4. 확인한 viewport·상태와 남은 가정
5. 제품 소스를 수정하지 않았다는 범위와 실제 구현에서 제외할 시안 전용 요소

## 품질 기준

- Before의 충실도는 픽셀 복제가 아니라 같은 데이터, 상태, 주요 동작과 정보 구조를 보존하는 것이다.
- 제품 UI 문자열과 시안 설명은 시각적·구조적으로 분리한다.
- After의 차이는 단순 장식이 아니라 명시한 문제 해결과 연결된다.
- 확인하지 못한 토큰, 기능, 데이터, 카피와 신뢰 표식을 제품 UI처럼 만들지 않는다.
- 정적 시안으로 검증하지 못한 상호작용과 접근성 동작은 남은 가정으로 표시한다.
