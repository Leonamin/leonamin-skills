# 감사 기준과 보고 형식

## 정적 검사

scripts/audit_design.py는 다음 항목을 휴리스틱으로 찾는다.

- 토큰 파일 밖의 색상처럼 보이는 hex 값
- 과도한 radius, 그림자, 그라디언트와 blur 관련 Tailwind 클래스
- 보라색·파란색 그라디언트 편향
- 중첩되거나 파일 안에서 과도하게 반복되는 Card
- 일반적인 마케팅 문구
- 선택적인 design-product manifest 존재 여부

경고와 정보 항목은 조사할 신호다. 오류도 실제 코드 구조와 화면에서 확인한 뒤 결함으로 보고한다.

## 화면 감사

- 사용자 목표와 주요 행동이 분명한가
- 정보 계층과 콘텐츠 순서가 의사결정을 돕는가
- 색상, 타이포그래피, 간격과 컴포넌트가 기존 시스템과 일치하는가
- 키보드, 포커스, 레이블과 대비가 적절한가
- 좁고 넓은 화면에서 가림, 넘침과 잘못된 고정 요소가 없는가
- 로딩, 오류, 빈 상태와 비활성 상태를 이해할 수 있는가
- 제품 고유의 정보와 행동이 장식보다 앞서는가

## 우선순위

- 높음: 핵심 작업을 막거나 접근성·정확성에 영향을 줌
- 중간: 흐름을 어렵게 하거나 반복적으로 혼란을 만듦
- 낮음: 기능 영향 없이 일관성이나 완성도를 개선함

## 보고 형식

발견 사항부터 작성한다.

~~~text
발견 사항
- [높음] file:line 또는 화면 위치
  - 근거:
  - 사용자 영향:
  - 권장 조치:

검증
- 실행한 검사와 확인한 화면:

남은 위험
- 미확인 또는 후속 작업:
~~~

발견 사항이 없으면 없다고 명시하고, 확인하지 못한 화면이나 상태를 함께 적는다.
