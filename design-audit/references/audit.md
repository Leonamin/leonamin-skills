# 감사 기준과 보고

**사용자 영향이 큰 문제부터 보고하고, 자동 검사 신호와 확인된 결함을 구분한다.**

## 화면 기준

- 목표·주요 행동·정보 순서가 명확하고 판단에 필요한 정보가 보이는가?
- 인접한 라벨·제목·소개문이 같은 뜻을 반복하는가? 제거해도 폼 라벨·접근성 이름·필수 안내가 유지되는가?
- 색상·타이포·간격·컴포넌트가 기존 시스템과 일치하며, 장식이 실제 콘텐츠보다 과도하게 강조되지 않는가?
- 키보드·포커스·라벨·대비가 적절한가?
- 좁고 넓은 화면에서 가림·넘침·잘못된 고정 요소가 없는가?
- 로딩·오류·빈 상태·비활성 상태의 의미와 다음 행동을 이해할 수 있는가?

## 정적 신호

`audit_design.py`는 웹 코드에서 원시 hex, 장식용 Tailwind 클래스, 색상 편향, Card 중첩·과다 사용, 일반적인 영문 마케팅 문구를 찾는다. 제품 맥락과 렌더링 결과를 확인하기 전에는 결함으로 확정하지 않는다. 의미상 반복 문구·실제 접근성·반응형 동작은 이 스크립트만으로 판정할 수 없다.

`--strict`는 error 신호가 있으면 실패 코드를 반환한다. 프로젝트가 해당 규칙을 오류로 확정해 CI에서 사용하기로 한 경우에만 적용한다. 선택적인 `design-product/manifest.json`의 부재는 결함이 아니다.

## 보고

각 발견 사항은 `우선순위 · 파일:줄 또는 화면 위치 · 근거 · 사용자 영향 · 최소 조치`로 작성한다.

- 높음: 핵심 작업을 막거나 접근성·정확성에 영향을 줌
- 중간: 반복적인 혼란이나 작업 지연을 만듦
- 낮음: 기능 영향 없이 일관성·완성도를 개선함

끝에는 감사 범위, 수행한 검사·확인한 화면과 미확인 상태를 남긴다. 스크린샷 관찰, 코드 분석, 실제 동작 검증의 근거를 구분한다.
