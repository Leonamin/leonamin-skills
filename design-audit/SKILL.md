# GUI 디자인 감사

기존 GUI를 실제 코드와 화면 증거로 검토하고, 사용자 영향이 큰 문제부터 최소 변경안을 제시한다.

## 권한과 경계

- 감사·검토 요청은 읽기 전용이다. 파일, 디자인 시스템, 감사 기록을 수정하지 않는다.
- 사용자가 개선을 명시적으로 요청한 경우에만 합의된 범위를 구현한다.
- 감사 결과나 장기 결정을 프로젝트에 기록하는 작업도 별도 요청이 있을 때만 수행한다.
- 제품 정체성, 토큰 체계 또는 전체 IA를 새로 정해야 하면 $design-product로 인계한다.
- Figma 산출물 생성·수정은 $figma-design으로 인계한다.

## 진행

1. 대상 화면·컴포넌트·플로우와 제외 범위를 정한다.
2. 저장소의 디자인 문서, 토큰과 제품 컴포넌트를 찾는다. design-product/manifest.json이 있으면 관련 항목만 읽되, 없어도 감사를 중단하지 않는다.
3. 다음 스크립트를 실행해 정적 신호를 수집한다.

   ~~~bash
   python3 <skill-dir>/scripts/audit_design.py --path <repo>
   ~~~

   CI에서 확실한 오류를 실패로 처리할 때만 --strict를 사용한다. 스크립트 결과는 판정이 아니라 조사할 신호다.
4. 코드, 실제 화면 또는 제공된 스크린샷을 대조하고 주요 흐름, 키보드 접근성, 좁고 넓은 화면, 로딩·오류·빈 상태를 확인한다.
5. 발견 사항에 위치, 근거, 사용자 영향과 최소 권장 조치를 기록한다. 감사 기준과 보고 형식은 [references/audit.md](references/audit.md)를 따른다.
6. 구현이 요청됐다면 기존 토큰과 제품 컴포넌트를 우선해 수정하고, 같은 정적 검사와 실제 화면으로 검증한다.

## 하드 룰

- 자동 검사 결과만으로 디자인 결함을 확정하지 않는다.
- 근거 없이 원시 색상, 장식용 그라디언트, 과도한 카드·그림자·radius를 추가하지 않는다.
- 접근성, 반응형 동작과 상태 표현을 시각적 취향보다 먼저 확인한다.
- 가짜 데이터, 후기, 수치 또는 신뢰 표식을 만들지 않는다.
- 실제 변경과 검증 없이 문제가 개선됐다고 주장하지 않는다.

## 완료 결과

- 감사 범위
- 우선순위별 발견 사항과 근거
- 권장 변경안 또는 구현한 파일
- 수행한 정적 검사와 화면 검증
- 남은 위험과 후속 작업

기록을 요청받지 않았다면 memory나 last-audit.md를 완료 결과에 포함하지 않는다.
