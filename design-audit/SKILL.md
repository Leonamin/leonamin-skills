# GUI 디자인 감사

**실제 사용을 방해하는 문제부터 근거와 최소 수정안을 제시한다.**

감사 요청은 읽기 전용이다. 개선도 요청받았다면 해당 범위를 구현한다. 별도 기록은 요청받았을 때만 남기고, 디자인 시스템·운영 데이터 변경으로 범위를 확대하지 않는다.

## 진행

1. 대상 화면·상태·주요 흐름과 범위를 정하고 기존 디자인 문서·토큰·공용 컴포넌트를 확인한다. `design-product/manifest.json`은 있을 때만 참고한다.
2. [감사 기준](references/audit.md)으로 확보한 코드·실제 화면·스크린샷을 검토하고 가능한 근거를 대조한다. 반복 문구는 [UI 문구 절제 기준](../design-product/references/ui-copy.md)으로 판단한다.
3. 웹 코드의 정적 신호가 필요하면 `python3 <skill-dir>/scripts/audit_design.py --path <repo>`를 실행한다. 결과는 조사할 신호이며 결함 판정이 아니다. 코드가 없거나 검사 대상 스택이 아니면 생략한다.
4. 실행 환경이 있으면 핵심 흐름·키보드·좁고 넓은 화면·로딩·오류·빈 상태를 확인한다. 스크린샷만으로 상호작용이나 접근성 동작을 검증했다고 하지 않는다.
5. 사용자 영향 순으로 위치·근거·영향·최소 조치를 보고한다. 구현했다면 기존 토큰·컴포넌트를 우선하고 관련 화면과 검사를 다시 확인한다.

## 판단과 결과

- 접근성·정확성·핵심 작업을 시각적 취향보다 우선한다. 기존 디자인과 장식이 사용자 목표에 도움이 되는지 판단하며 개인 취향을 결함으로 보고하지 않는다.
- 확인하지 않은 데이터·후기·수치·신뢰 표식을 만들거나, 검증 없이 개선을 주장하지 않는다.
- 발견 사항을 먼저 제시하고 감사 범위·검증·미확인 상태를 짧게 덧붙인다. 문제가 없으면 없다고 명시한다.

정체성·전체 IA·토큰 체계의 재설계가 필요하면 `$design-product`, 편집 가능한 Figma 제작은 `$figma-design`을 사용한다.
