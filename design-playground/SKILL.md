# Design Playground

**좋은 레퍼런스에서 시작해 사용자가 화면을 보며 조정하고, 선택한 규칙과 구조를 구현까지 이어간다.**

기본 산출물은 조정 가능한 화면과 저장·재적용 가능한 선택본이다. 이미지 생성은 필요한 사진·일러스트 등 자산에 사용하며 화면 전체를 정적 이미지로 대체하지 않는다. 탐색 요청만으로 제품 소스·공식 디자인 시스템·운영 데이터를 바꾸지 않는다. 이미 구현까지 요청받았다면 선택한 결과로 이어가며 승인을 반복 요구하지 않는다.

## 기준 화면

1. 대상·주요 행동·콘텐츠·화면 크기를 파악하고 레퍼런스 화면을 직접 본다. 기존 제품이면 코드·컴포넌트·토큰·디자인 문서를 확인한다. 자료로 확인 가능한 내용을 다시 묻지 않는다. 레퍼런스가 없으면 관련 화면이나 후보를 찾아 출발점을 제안하고, 접근 불가·추정 사항은 밝힌다.
2. 레퍼런스마다 가져올 부분과 유지할 제품 제약을 정한다. 예: A의 목록 밀도, B의 제목 위계, 기존 제품의 버튼과 색상. 관찰한 구조·추정한 치수와 실제 코드에서 확인한 값을 구분한다. 브랜드·기능·정책·수치를 레퍼런스에서 무심코 가져오지 않는다.
3. 실제 콘텐츠나 일관된 예시 데이터로 HTML/CSS/JS 또는 기존 스택을 활용한 실행 화면을 만든다. 재사용 가능한 기존 컴포넌트를 우선하며 제목을 반복하는 소개문은 [UI 문구 절제 기준](../design-product/references/ui-copy.md)으로 제거한다. 결과가 레퍼런스에서 선택한 특징을 반영했는지 직접 확인한다.

## 조정과 비교

- [조정과 선택본](references/controls-and-selection.md)에 따라 이 화면에서 판단할 가치가 있는 컨트롤만 만든다. 값·단위·적용 범위를 보이고 변경을 즉시 화면에 반영한다. 조정 패널·비교 설명은 제품 UI 밖에 둔다.
- 간격·색상 등 값 조정과 함께 배치 이동·목록 형식·정보 노출 같은 구조 수정도 지원한다. 모든 구조를 범용 편집기로 만들 필요는 없다. 자주 비교할 선택은 컨트롤로, 나머지는 대화로 수정하되 이미 선택한 규칙을 유지한다.
- 기준안과 현재안을 같은 데이터·상태·viewport·배율로 비교하고 초기화할 수 있게 한다. 여러 방향은 요청이나 실제 트레이드오프가 있을 때만 만들며 후보 수를 채우지 않는다.
- 미적 점수보다 주요 행동의 가시성·정보 위계·가독성·일관성에 미치는 효과를 설명한다. 취향과 기능 결함을 구분하고 모델의 추천을 사용자 확정값으로 기록하지 않는다.
- 긴 콘텐츠·빈 데이터 등으로 판단이 달라질 때 [상태 선택](references/states.md)을 읽고 필요한 상태를 전환해 확인한다. 기능은 탐색에 필요한 만큼 구현하고 mock과 실제 연동을 구분한다.

## 저장·검증·인계

- 산출물은 플랫폼 작업 디렉터리 또는 저장소 밖에 둔다. 사용자가 지정한 위치는 따른다. 화면 규모에 맞는 최소 실행 방식을 선택하고 실행 경로·주소를 제공한다.
- 브라우저에서 화면을 직접 보고 컨트롤 변경, 기준안 복원, 새로고침 후 복원, 선택본 내보내기·다시 불러오기를 검증한다. 구조 수정 뒤에도 선택값이 적용되는지 확인한다. 필요한 viewport·상태에서 잘림·겹침·읽기 어려움을 수정한다. 사용 가능한 도구나 `$agent-browser`를 쓰고 실행하지 못한 검증은 명시한다.
- 실행 원본, 참고자료와 채택한 특징, 선택본, 주요 구조 변경과 남은 가정을 함께 전달한다. 조정 중인 값과 사용자가 확정한 값을 구분한다. 선택 전이라도 작동하는 탐색 결과와 현재값을 제공할 수 있다.
- 구현에서는 화면 원본과 선택값을 재사용한다. 시안 전용 조정 패널은 제외하고 값·컴포넌트·구조를 실제 코드에 대응시킨다. 선택본은 탐색 산출물이며 기존 토큰 원본과 경쟁하는 공식 시스템으로 만들지 않는다.

## 인접 작업

사용 가능한 스킬 중 필요한 것만 적용하고, 없으면 해당 작업을 수행한다.

- 제품 전체 정체성·IA·디자인 시스템 결정: `$design-product`.
- 특정 개선의 정적 Before/After 비교: `$ui-before-after-sketch`. 직접 조정이 필요할 때 이 스킬을 사용한다.
- 확정된 기준의 DESIGN.md 반영: `$manage-design-md`. 화면 탐색만으로 공식 기준을 갱신하지 않는다.
- 앱의 실제 기능·데이터 흐름 완성: `$make-prototype`. Playground를 필수 선행 단계로 추가하지 않는다.
