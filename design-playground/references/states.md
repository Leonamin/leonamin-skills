# 상태 선택

**디자인 판단이나 다음 행동이 달라지는 상태만 확인하고, 확인된 정책과 제안을 구분한다.**

| 상태 | 확인할 차이 |
| --- | --- |
| 정상 | 정보 우선순위·주요 행동 |
| 전체 빈 데이터 / 검색 결과 없음 | 최초 행동 / 조건 해제·검색 수정 |
| 초기 / 갱신·추가 로딩 | 데이터 없는 구조 / 기존 콘텐츠 유지·진행 표시 |
| 전체 / 일부 조회·이미지 실패 | 전체 복구 / 정상 영역 유지·부분 대체 |
| 업무·권한 조건 | 확인된 결제·취소·접근 제한과 가능한 행동 |
| 콘텐츠 경계 | 긴 제목·누락 이미지·많은 항목의 배치 변화 |

모든 조합을 만들지 않는다. 공통 구조와 선택한 규칙을 유지하며 달라지는 영역을 확인한다. 배지만 바뀌면 컴포넌트, 정보 구조나 다음 행동이 바뀌면 해당 영역이나 화면을 비교한다.

상태별 노출 조건·정보·행동·근거 또는 가정을 필요한 만큼 기록한다. 겹치는 조건의 우선순위와 복구 방법은 실제 코드·정책으로 확인한다. 확인된 문자열이 없으면 제안임을 표시하고, 알 수 없는 업무 정책을 작동하는 사실로 만들지 않는다.

Playground의 상태 전환은 탐색용 시뮬레이션일 수 있다. 정적 비교는 해당 상태의 표현만 확인한다. 실제 연동·권한·키보드·반응형·상태 전환 중 검증하지 않은 부분은 구현 검증 대상으로 전달하며 시안에 없다는 이유로 필요한 행동을 삭제하지 않는다.
