# 리뷰 검수 자료 준비

**리뷰어가 무엇을 어디서 찾아 비교할지 프로젝트 근거로 기록한다.**

자료 생성·갱신만 수행한다. 제품 코드·스키마·기존 지침·CI를 바꾸거나 실제 리뷰·PR 게시로 범위를 확대하지 않는다. 특정 프레임워크·폴더·DB를 가정하지 않는다.

## 진행

1. 지정 범위 또는 현재 프로젝트의 지침·패키지·진입점으로 앱·언어·배포 단위를 파악한다. 모노레포의 앱 경계를 유지한다.
2. [자료 계약](references/context-contract.md)에 따라 기존 경로나 기본 `.review-context/`에 `index.md`와 필요한 영역만 작성한다. Git 상태 또는 비Git 파일 지문으로 조사 기준을 남긴다.
3. 공용 후보의 정의·export·대표 호출부·테스트/스토리를 읽고 외부 라이브러리와 wrapper 관계를 확인한다. 이름·사용 횟수만으로 표준을 지정하지 않는다.
4. 아래 영역 중 해당 범위를 조사하고 확인 상태·검색 범위·미해결 충돌을 기록한다. 공통 판단은 [review-run 기준](../review-run/references/criteria.md)을 참고한다.

| 영역 | 조사할 근거 |
| --- | --- |
| UI | 기본 동작·입력·알림·overlay·레이아웃·상태 계약 |
| 에러 | handler·middleware·응답·로그·사용자 메시지 경로 |
| 구조·상태 | 도메인·의존 방향·서비스/훅/controller의 책임과 사용처 |
| 데이터 | schema/model/migration의 의미·소유자·관계·writer·이력/스냅샷/캐시 구분 |

명시된 정책과 관찰된 관행을 구분한다. 기존 중복·나쁜 설계를 표준으로 학습하거나 충돌하는 자료의 우선순위를 임의로 정하지 않는다. 생성 자료·vendor·build·lockfile·생성 코드는 공용 구현으로 오인하지 않는다.

갱신 시 영향받은 정의·호출부·정책과 이동·삭제된 참조를 재확인한다. 사용자 설명·결정·예외를 보존한다. 로컬 자료부터 조사하고 배포 스키마는 확인한 경우만 단정한다. 비밀값·환경 파일 내용·운영 데이터를 수집하지 않는다.

저장 위치·조사 범위·미조사/충돌·기준 revision을 보고한다. 자료 준비를 실제 리뷰 완료로 표현하지 않는다.
