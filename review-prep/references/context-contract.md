# 프로젝트 검수 자료 계약 v1

이 자료는 탐색용 지도다. 리뷰 시 원본 코드로 근거를 재검증한다. 파일 전체를 매번 프롬프트에 넣지 않고 `index.md`에서 관련 영역만 찾아 읽는다.

## index.md

다음을 기록한다.

- `schema_version: 1`
- 프로젝트 식별: 저장소 이름 또는 디렉터리 식별자. 재사용을 위해 소스 참조는 저장소 상대 경로로 쓴다.
- 생성 시각, Git HEAD와 branch, dirty 여부. 비Git이면 조사 파일의 내용 지문과 기준 시각.
- 조사한 소스 상태: commit만 조사했는지 working tree까지 조사했는지. dirty 파일을 읽었다면 해당 파일의 내용 지문을 남겨 HEAD만으로 최신성을 판단하지 않는다.
- 앱·패키지별 언어, 역할, 경계와 관련 영역 자료 링크.
- 영역별 상태, 검색 범위, 제외 범위와 미해결 사항.
- 명시적 프로젝트 정책의 원본 위치와 적용 범위. 단순 관찰과 구분한다.

`.review-context/`를 커밋할지는 프로젝트 정책을 따른다. 자동 커밋하거나 ignore 규칙을 변경하지 않는다.

## 영역 자료

파일명은 영역에 맞게 정한다. 예: `ui.md`, `errors.md`, `architecture.md`, `data.md`. 대규모 모노레포는 앱 단위로 나눈다. 모든 컴포넌트의 소스를 복사하는 대신 책임별 후보와 검색 진입점을 기록한다.

각 항목에 다음 정보를 포함한다.

| 필드 | 내용 |
|---|---|
| ID | 자료 안에서 안정적으로 참조할 식별자 |
| 책임 | 수행하는 동작과 소유하는 상태·데이터 |
| 범위 | 앱/패키지/도메인, 공개 API 여부, 사용 가능한 의존 방향 |
| 정의 | 원본 상대 경로와 symbol; 줄 번호는 보조 정보 |
| 기능과 한계 | props, 응답 계약, 지원 상태, 확장 지점 등 재사용 판단에 필요한 정보 |
| 근거 | 대표 호출부, 테스트/스토리, 명시적 지침 위치 |
| 상태 | 확인됨, 후보 충돌, 미발견, 해당 없음, 미조사 |
| 판단 구분 | 명시된 표준인지 관찰된 구현인지 |
| 검증 기준 | 조사 revision 또는 관련 dirty/비Git 파일의 지문 |
| 불확실성 | 경쟁 후보, legacy 여부, 추가 확인할 의미 |

데이터 항목에는 entity/field의 의미, 소유자, 관계와 쓰기 경로를 우선 기록한다. 원본 schema를 그대로 복제하지 않는다. 소스 schema와 실제 배포 schema를 동일시하지 않는다.

## 갱신과 리뷰 시 유효성

- 대상 revision과 자료 기준이 다르면 관련 정의·호출부·정책의 변경 여부를 확인한다.
- 자료에 없는 신규 구현도 리뷰 범위에 포함한다. 목록 부재는 중복 부재의 증거가 아니다.
- 공용 구현 후보가 여럿이면 비교 근거를 남긴다. 가장 많이 쓰이는 구현을 자동으로 정답으로 삼지 않는다.
- 자료가 낡았거나 없으면 리뷰어가 관련 범위를 읽어서 보완할 수 있다. 확인할 수 없는 영역은 판정 보류하고, 전체 prep 실행을 매 리뷰의 필수 조건으로 삼지 않는다.
- 검토 대상 변경이 자료나 정책도 수정했다면 기준 revision의 정책과 비교한다. 변경된 정책으로 그 변경 자체를 자동 정당화하지 않는다.
