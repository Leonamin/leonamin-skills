# 프로젝트 검수 자료 계약 v1

**자료는 탐색용 지도다. 리뷰 판단은 원본 코드와 현재 계약으로 재검증한다.**

## index.md

- `schema_version: 1`, 프로젝트 식별자와 생성 시각
- Git HEAD·branch·dirty 상태와 commit/working tree 조사 구분. 읽은 dirty 파일은 내용 지문을 남긴다. 비Git은 조사 파일 지문과 기준 시각을 기록한다.
- 앱·패키지의 언어·역할·경계와 영역 자료 링크
- 영역별 상태·검색/제외 범위·미해결 사항
- 명시적 정책의 원본과 적용 범위; 관찰된 관행과 구분

참조는 저장소 상대 경로로 기록한다. `ui.md`·`errors.md`·`architecture.md`·`data.md` 등 필요한 영역만 만들고 큰 모노레포는 앱별로 나눈다. 소스 전체 대신 책임별 후보와 검색 진입점을 남긴다. 자료를 자동 커밋하거나 ignore 설정을 바꾸지 않는다.

## 항목 계약

| 정보 | 기록할 내용 |
| --- | --- |
| 식별·책임 | 안정적인 ID, 동작·소유 상태/데이터 |
| 범위·정의 | 앱/도메인·공개 API·의존 방향, 원본 경로·symbol; 줄 번호는 보조 |
| 기능·근거 | 지원 상태·계약·한계·확장 지점, 대표 호출부·테스트/스토리·지침 |
| 상태·판단 | 확인됨 / 후보 충돌 / 미발견 / 해당 없음 / 미조사; 명시 표준인지 관찰인지 |
| 기준·불확실성 | revision 또는 dirty/비Git 지문, 경쟁 후보·legacy·추가 확인 사항 |

`미발견`에는 검색 범위, `해당 없음`에는 근거를 남긴다. 부분 조사를 전수 조사로 표시하지 않는다. 데이터는 의미·생명주기·소유자·관계·쓰기 경로를 기록하고 schema를 복제하거나 배포 상태와 동일시하지 않는다.

## 유효성

- 자료와 대상 기준이 다르면 관련 정의·호출부·정책 변경을 확인한다. 신규 구현도 검토하며 목록 부재를 중복 부재의 증거로 삼지 않는다.
- 경쟁 공용 후보는 비교 근거를 남기고 사용량만으로 정답을 정하지 않는다.
- 자료가 낡았거나 없으면 관련 소스를 직접 읽어 보완한다. 전체 prep을 매 리뷰의 필수 조건으로 삼지 않으며 미확인 영역은 판정을 보류한다.
- 검토 변경이 정책·자료도 바꾸면 기준 revision과 비교한다. 변경된 규칙으로 그 변경 자체를 자동 정당화하지 않는다.
