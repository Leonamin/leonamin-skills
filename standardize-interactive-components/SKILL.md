# 인터랙션 컴포넌트 표준화

**사용자 의도에 맞는 HTML 의미와 기존 공용 계약으로 인터랙션을 통합한다.**

조사 요청은 읽기 전용이다. 구현 요청에는 해당 범위의 코드와 검사를 수정한다.

## 의미와 계약

| 의도 | 기본 의미 | 기존 컴포넌트 예시 |
| --- | --- | --- |
| 명령 | `button` | Button, IconButton |
| 이동 | `a` | AppLink, LinkButton |
| 선택 | `input`과 label 또는 검증된 접근성 패턴 | Checkbox, Radio, Switch |
| 파일 선택 | `input[type=file]`과 접근 가능한 trigger | FilePicker |
| 표시 | 비인터랙티브 컨테이너 | Card |

- 이름·외형보다 실제 렌더링과 동작으로 판단한다. 기존 API로 반복 의도를 표현할 수 없을 때만 작은 컴포넌트·variant를 추가하고 다른 제품의 시각 변형까지 거대한 API로 합치지 않는다.
- 클릭·cursor만 붙인 컨테이너 대신 실제 링크·버튼·선택 요소를 기본 경로로 둔다. 링크·버튼 안에 인터랙티브 요소를 중첩하지 않는다. 내부 액션이 있는 카드는 표시 컨테이너와 독립 액션을 조합한다.
- 행 클릭은 `tr`의 table 의미와 셀의 기본 링크·버튼 경로를 유지한다. 아이콘 액션에 접근 가능한 이름을 주고 키보드는 요소의 기본 의미를 따른다. cursor·disabled 표현은 프로젝트 정책을 따르며 pointer를 일괄 강제하지 않는다.

## 진행과 검증

1. 대상·공용 컴포넌트·디자인 정책·검증 명령을 확인하고 raw 요소·비시맨틱 클릭·선택·중첩 액션 후보를 수집한다. React TSX/JSX에는 [감사 도구](references/audit-tool.md)를 사용할 수 있다. 다른 문법은 프로젝트 도구나 직접 조사로 확인한다.
2. 후보를 이전·근거 있는 예외·후속 범위로 분류한다. 원시 HTML 자체는 결함이 아니며 primitive 내부에도 필요하다. backdrop·이벤트 전파 차단·보조 행 클릭은 실제 동작으로 판단한다.
3. 구현 후 관련 lint·타입 검사·회귀 테스트를 수행한다. 재발 방지 검사는 프로젝트가 채택한 규칙과 좁은 예외로 ESLint·source-policy에 반영한다.
4. 실제 route나 Storybook에서 Tab·요소에 맞는 Enter/Space·disabled·중첩 액션·모바일 hit area를 확인한다. cursor 정책은 computed style로 확인한다. 정적 결과나 태그 수 감소로 접근성·스타일·동작 개선을 단정하지 않는다.

검사·제외 범위, 후보별 처리와 변경, 자동·화면 검증 결과와 남은 위험을 보고한다.
