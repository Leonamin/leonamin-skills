# 인터랙션 컴포넌트 표준화

사용자 의도를 기준으로 인터랙션을 분류하고 프로젝트의 기존 컴포넌트와 정책에 맞춰 정리한다. 조사 요청은 읽기 전용으로 수행하고, 구현 요청일 때 해당 범위의 코드와 검사를 변경한다.

## 의미와 계약

| 의도 | 기본 HTML 의미 | 기존 컴포넌트 예시 |
| --- | --- | --- |
| 명령 실행 | `button` | Button, IconButton |
| 이동 | `a` | AppLink, LinkButton |
| 선택 | `input`과 연결된 label 또는 검증된 접근성 패턴 | Checkbox, Radio, Switch |
| 파일 선택 | `input[type=file]`과 접근 가능한 trigger | FilePicker |
| 표시 전용 | 비인터랙티브 컨테이너 | Card |

- 이름과 외형보다 실제 렌더링과 사용자 의도를 확인한다. 컴포넌트 이름이나 특정 prop 설계를 강제하지 않는다.
- 기존 공용 컴포넌트를 우선한다. 반복되는 의도를 기존 API로 표현할 수 없을 때만 작은 컴포넌트나 variant를 추가한다.
- 비시맨틱 컨테이너에 클릭만 붙이거나 cursor만 추가해 동작을 구현하지 않는다. 사용자 의도에 맞는 실제 링크·버튼·선택 요소를 기본 접근 경로로 둔다.
- 링크·버튼 안에 다른 인터랙티브 요소를 중첩하지 않는다. 내부 액션이 있는 카드는 표시 컨테이너와 독립된 액션을 조합한다.
- 행 전체 클릭을 제공해도 `tr`의 table 의미와 셀 안의 기본 링크·버튼 접근 경로를 유지한다.
- 아이콘 전용 액션에 접근 가능한 이름을 제공한다. 키보드 동작은 요소의 기본 의미에 맞춘다.
- cursor와 disabled 표현은 프로젝트 디자인 정책에 맞춘다. 모든 요소에 pointer를 일괄 강제하지 않는다.
- 서로 다른 제품의 시각 variant까지 하나의 거대 컴포넌트로 합치지 않는다.

## 진행

1. 대상 화면·소스 범위, 기존 공용 컴포넌트, 디자인 정책과 검증 명령을 확인한다.
2. raw 요소, 비시맨틱 클릭, 선택 컨트롤과 중첩 액션의 후보를 수집한다. React의 TSX/JSX 소스에는 [감사 도구 사용법](references/audit-tool.md)을 읽고 번들 스크립트를 사용할 수 있다. 다른 문법은 해당 프로젝트 도구나 직접 조사로 확인하고 자동 검사 범위를 명시한다.
3. 각 후보를 기존 컴포넌트로 이전, 근거 있는 예외, 후속 범위로 분류한다. 원시 HTML 자체는 결함이 아니며 공용 컴포넌트의 내부 구현에도 필요하다. backdrop 닫기, 이벤트 전파 차단과 보조 행 클릭도 실제 동작을 보고 판단한다.
4. 구현이 요청됐다면 확인된 범위를 수정하고 회귀 위험에 맞는 lint·타입 검사·테스트를 수행한다. 새 위반을 차단할 때는 프로젝트가 채택한 규칙과 좁은 예외를 ESLint 또는 source-policy 검사로 고정한다.
5. 실제 route나 Storybook에서 Tab, 요소에 맞는 Enter/Space, disabled 상태, 중첩 액션과 모바일 hit area를 확인한다. cursor 정책이 있으면 computed style로 검증한다. 정적 스크립트는 실제 접근성·스타일 검증을 대신하지 않는다.

## 완료 결과

검사한 범위와 제외 범위, 후보별 처리, 변경 사항, 자동 검사와 실제 화면 검증 결과, 남은 위험을 보고한다. 태그 수 감소나 정적 검사 통과만으로 동작 개선 또는 접근성 검증 완료를 주장하지 않는다.
