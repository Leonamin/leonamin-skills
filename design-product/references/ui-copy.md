# UI 문구 절제 기준

**제목을 반복하는 라벨·소개문은 제거하고, 판단·행동에 필요한 새 정보만 남긴다.**

## 적용

- 제목·주요 액션·데이터부터 배치한다. `상단 라벨 + 제목 + 보조 제목 + 소개문`을 고정 구조로 만들지 않는다.
- 설명마다 “없으면 사용자가 무엇을 모르거나 잘못하게 되는가?”를 묻는다. 답이 없으면 삭제한다. `한곳에서 효율적으로 관리하세요` 같은 홍보 문구로 빈자리를 채우지 않는다.
- 필요한 설명은 관련 필드·액션 가까이에 둔다. 이해하기 어려운 조작은 이름·배치·흐름부터 고친다.
- 공용 헤더의 `description`·`eyebrow`는 선택 항목으로 둔다. 누락 시 기본 소개문·빈 wrapper·설명용 여백을 만들지 않는다.

## 유지

- 폼 label/legend, 접근성 이름, 구조를 전달하는 시맨틱 제목.
- 입력 제한, 공개 범위, 비용, 권한, 되돌릴 수 없는 결과와 오류 복구 안내. 필수 정보는 접힌 도움말에 숨기지 않는다.
- 역할이 다른 반복. 메뉴와 페이지 제목의 `설정`은 탐색과 현재 위치 식별을 각각 담당할 수 있다.
- 빈 상태의 다음 행동, 온보딩의 낯선 개념 설명, 마케팅의 가치 제안. 목적에 필요한 정보인지 판단하며 문장 수를 일률적으로 제한하지 않는다.

## 예시

- `WORKSPACE → 콘텐츠 → 콘텐츠를 한곳에서 관리하세요 → 목록`은 `콘텐츠 + 새 콘텐츠 버튼 + 목록`으로 줄인다.
- `파일을 업로드할 수 있습니다`는 생략한다. 지원 형식·크기 제한은 확인된 값으로 안내한다.

실제 화면에서 문구를 덜어낸 뒤에도 위치·작업·상태를 이해할 수 있는지 확인한다. 문자열이 같다는 이유만으로 삭제하지 않는다.
