# 프로젝트 위키

**현재 작업에 필요한 지식을 찾아 활용하고, 요청받은 범위에서만 위키와 설정을 변경한다.**

## 작업 선택

- 조회·설명·작업 근거 확인은 읽기 전용이다. 새 문서·인덱스·로그·설정을 만들지 않는다.
- 확정 지식의 기록·갱신을 요청받으면 [갱신 절차](references/update.md)를 적용한다.
- 초기 설정·구조 재설계를 요청받으면 [설정 절차](references/setup.md)를 적용한다. 조회나 기록 요청을 위키 초기화·이관으로 확대하지 않는다.
- 이미 지정한 작업과 범위는 다시 승인받지 않는다. 여러 작업을 요청받았다면 필요한 절차만 함께 적용한다.

## 공통 경로와 기준

1. Git 프로젝트 루트를 확인하고 비Git은 현재 작업 디렉터리를 기준으로 한다.
2. 요청 경로 → `.agents/wiki-path` → `.env`의 `WIKI_PATH` → 세션에서 확인한 경로 순으로 찾는다. 상대 경로는 프로젝트 루트 기준이다. 환경 파일에서는 필요한 경로만 확인하고 비밀값을 노출하지 않는다.
3. 경로가 없거나 초기화되지 않았으면 그 사실을 보고한다. 설정까지 요청받은 경우에만 설정 절차로 진행하고, 그 외에는 경로·초기 설정이 필요함을 안내한다.
4. 프로젝트 `.agents/wiki-structure.md`와 위키 루트 `index.md`를 확인한다. 기존 구조·문서·설정을 보존하며, 구조 설정이 없으면 해당 범위의 인덱스를 기준으로 판단한다.

## 읽기와 해석

- 제목·설명·태그·링크로 관련 문서를 고르고, 선택한 디렉터리의 인덱스를 읽은 뒤 필요한 문서로 이동한다. 모든 문서를 일괄 읽지 않는다.
- 결정 변경이나 시간 흐름이 중요하면 `logs/index.md`와 관련 로그를 확인한다. 루트 `log.md`는 기존 기록으로 구분한다.
- Decision의 Status와 현재 유효성을 확인하고 Superseded 결정을 현재 규칙으로 적용하지 않는다. Concept에서는 정의·전제·관계·제약을, Reference에서는 외부 출처와 적용 범위를 추출한다.
- 문서 충돌을 임의로 해소하지 않는다. 오래된 내용은 필요하면 현재 코드·설정·테스트와 대조하고 확인 여부를 밝힌다.
- 기록된 사실·결정, 다른 근거와 추론을 구분한다. 위키에 없는 내용은 기록되지 않았다고 밝히고 결정을 만들지 않는다.

현재 작업에 미치는 영향부터 답하고 필요한 사실·제약·결정·충돌·추가 확인과 문서 링크를 남긴다. 단순 질문에는 짧게 답한다. 쓰기 작업은 변경 위치·검증·미확인 사항을 보고하며, 인덱스·로그 등 요청 범위의 필수 갱신이 빠졌으면 완료로 표현하지 않는다.
