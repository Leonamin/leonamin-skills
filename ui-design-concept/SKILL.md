# UI Design Concept

이미지로 디자인 방향을 탐색하고 상태별 화면 기준을 전달한다. 시안은 정보 우선순위와 시각적 의도를 공유하는 기준이며, 픽셀 단위 구현 명세나 동작 검증 결과가 아니다.

## 범위

- 시안 요청으로 제품 소스·디자인 시스템·업무 정책을 변경하지 않는다. 산출물은 작업용 디렉터리에 만든다.
- 사용자가 HTML/CSS 비교를 요청하면 그 형식을 따른다. 이 스킬 때문에 이미지 생성으로 바꾸거나 이미지 시안 뒤에 HTML/CSS 단계를 의무적으로 추가하지 않는다.
- 이후 구현 요청은 일반 구현 작업으로 이어갈 수 있다. 특정 구현 스킬 호출을 필수로 묶지 않는다. 이미 구현까지 요청받았다면 시안 단계만을 이유로 승인을 반복해서 묻지 않는다.

## 1. 필요한 맥락 확인

대상 화면, 사용자와 주요 행동, 화면 크기·언어를 파악한다. 제공된 코드·문서·스크린샷과 관련 디자인 토큰·공용 컴포넌트를 필요한 만큼 확인한다. 시각 자료는 직접 보고, 참고 이미지와 실제 제품 화면의 역할을 구분한다.

- 확인 가능한 내용을 사용자에게 다시 묻지 않는다. 핵심 사용자 행동이나 유지해야 할 기능처럼 결과를 크게 바꾸는 빈칸만 질문한다.
- 기존 제품은 확인된 브랜드·탐색 구조·데이터 의미를 기준으로 삼는다. 새 화면은 사용자 설명과 명시한 가정으로 시작할 수 있다.
- 지정된 자료에 접근하지 못하면 그 한계를 알린다. 필수 구조를 확인할 수 없을 때 필요한 자료를 요청하고, 대체 근거로 진행할 수 있는 부분은 범위를 밝혀 진행한다.
- 유지할 것과 탐색할 것을 짧게 정리한다. 상태·가격·권한·주요 행동은 확인된 계약을 유지하고, 배치·강조·이미지 비중은 요청 범위에서 탐색한다. 새 필터·버튼·동작은 기능 제안임을 구분한다.

## 2. 상태 범위 정하기

대표 정상 화면과 함께 빈 데이터·로딩·오류·조건부 상태를 기본적으로 검토한다. 실제로 적용되는 상태를 고르고, 화면 구조나 다음 행동이 달라지는 상태를 시안에 포함한다. 상세 기준은 [상태 선택과 인계](references/states-and-handoff.md)를 읽는다.

모든 조합을 그리지 않는다. 전체 구조가 바뀌면 별도 화면, 배지·버튼·이미지만 바뀌면 컴포넌트 상태 비교로 보여준다. 제외한 상태와 미확정 조건은 기록한다. 사용자 요청이 특정 상태나 한 장으로 제한됐다면 그 범위를 우선한다.

## 3. 대표 이미지 생성

이미지를 생성하기 전에 [생성 브리프](references/generation-brief.md)를 읽는다.

- 사용자가 지정한 도구를 우선하고, 지정이 없으면 현재 하네스의 이미지 생성 기능을 사용한다. 사용 가능한 도구의 실제 호출·참조 이미지·출력 규칙을 따른다. 고정 모델명이나 특정 공급자 SDK를 요구하지 않는다.
- 이미지 도구가 없으면 실행 가능한 브리프와 참고자료 목록을 전달하고 미생성 상태를 알린다. 프롬프트만 작성하고 시안을 완성했다고 표현하거나, HTML/CSS로 몰래 대체하지 않는다.
- 일반 시안 요청은 대표 방향 1안으로 시작한다. 여러 방향을 요청하면 의미 있게 다른 2~3안 또는 요청한 수를 만든다. 방향의 수와 상태 화면의 수를 구분한다.
- 실제 참고 이미지를 도구에 첨부한다. 코드·문서에서 추출한 제약은 텍스트로 전달한다. 도구에 전달하지 않은 자료를 참조했다고 주장하지 않는다.
- 각 방향에는 식별 가능한 이름을 부여하고 결과 이미지와 연결한다. 화면 크기·언어·핵심 데이터는 비교 가능한 조건으로 유지한다.

## 4. 상태 확장과 검토

한 방향으로 진행하는 요청이면 생성한 대표 화면을 기준으로 필요한 상태까지 이어서 만든다. 여러 대안 중 선택이 필요한 경우에는 먼저 대표안들을 보여주고 선택 후 상태를 확장한다. 이미 선택한 안이 있으면 다시 선택을 요구하지 않는다.

- 대표 이미지를 참조해 예외 상태를 만든다. 상태마다 별개의 스타일을 발명하지 않고 헤더·탐색·타이포·간격·공용 컴포넌트를 유지한다.
- 생성된 이미지를 직접 확인해 필수 정보 누락, 임의 기능 추가, 문구·날짜·금액 오류, 잘림과 상태 간 불일치를 수정한다. 도구 제약으로 수정할 수 없는 부분은 인계에 남긴다.
- 이미지에서 표현된 버튼·필터가 실제로 작동한다고 주장하지 않는다. 반응형·키보드 접근·오류 복구 동작은 구현 검증 항목이다.
- 피드백은 선택한 이미지를 기준으로 반영한다. 확정된 결정은 유지하고 요청한 부분을 수정한다.

## 완료 결과

생성한 이미지를 사용자가 볼 수 있게 제시하고 다음 내용을 짧게 전달한다.

- 대표 방향과 필요한 상태별 시안 또는 컴포넌트 상태 비교
- 채택하거나 제안한 디자인 결정과 기능 변경
- 상태별 노출 조건·사용자 행동·확인 근거, 제외 상태와 미결정 사항
- 구현에서 유지할 의도와 조정 가능한 세부사항

플랫폼의 산출물 디렉터리를 사용하고 없으면 저장소 밖의 작업 디렉터리를 만든다. 재사용 가능한 브리프·상태표·생성 프롬프트와 이미지 경로 또는 도구가 제공한 결과 식별자를 간결한 인계 문서에 함께 보관한다. 로컬 저장이 불가능하면 응답으로 전달한다. 미리보기만 가능한 결과를 로컬 파일로 저장했다고 표현하지 않는다.

시안 작업의 완료와 구현 완료를 구분한다. 구현으로 이어갈 때는 선택한 이미지와 인계 정보를 전달하며, 불필요한 중간 목업을 다시 만들지 않는다.
