# 상태 선택과 인계

**구조나 다음 행동이 달라지는 상태를 보여주고, 확인된 정책과 디자인 제안을 구분한다.**

## 상태 선택

아래에서 제품에 해당하는 상태만 고른다. 모든 조합을 생성하지 않는다.

| 상태 | 확인할 차이 |
| --- | --- |
| 정상 | 정보 우선순위·주요 행동 |
| 전체 빈 데이터 / 검색 결과 없음 | 최초 행동 / 조건 해제·검색 수정 |
| 초기 / 갱신·추가 로딩 | 데이터 없는 구조 / 기존 콘텐츠 유지·진행 표시 |
| 전체 / 일부 조회·이미지 실패 | 전체 복구 / 정상 영역 유지·부분 대체 |
| 업무·권한 조건 | 확인된 결제·취소·접근 제한과 가능한 행동 |
| 콘텐츠 경계 | 긴 제목·누락 이미지·많은 항목의 배치 변화 |

상태마다 `노출 조건 / 정보 / 행동 / 근거·가정 / 산출물`을 남긴다. 겹치는 조건의 우선순위는 실제 코드·정책으로 확인하며 복구 방법을 디자인만으로 확정하지 않는다.

정상 화면을 기준으로 공통 구조를 유지한다. 배지만 달라지면 컴포넌트 비교, 별도 행동·구조가 생기면 해당 영역이나 화면을 보여준다. 생략한 상태와 이유를 남기고 상태표만으로 이미지를 생성했다고 주장하지 않는다.

## 인계

짧은 문서에 선택 방향·이미지 식별자, 유지할 정보 위계·행동·브랜드, 조정 가능한 간격·크기·반응형·컴포넌트 매핑, 상태 정보, 참고자료·프롬프트·결과 경로를 묶는다. 선택 전 방향은 후보로, 새 기능은 제안으로, 미확정 정책은 질문으로 구분한다.

실제 데이터·긴 콘텐츠·키보드·반응형·상태 전환은 구현 검증 항목으로 전달한다. 이미지가 확인된 정책과 충돌하면 정책을 보존하고 이미지 수정점을 밝힌다. 이미지에 누락됐다는 이유로 필요한 상태·행동을 구현에서 삭제하지 않는다.
