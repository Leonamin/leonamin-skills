# 위키 설정

**사용자와 위키 위치·구조를 정하고, 기존 문서를 보존하며 설정과 탐색 인덱스를 만든다.**

## 설정 결정

1. `git rev-parse --show-toplevel`로 프로젝트 루트를 확인한다. Git 저장소가 아니면 현재 작업 디렉토리를 기준으로 한다.
2. `.agents/wiki-path`, `.agents/wiki-structure.md`, `.env`의 `WIKI_PATH`와 기존 위키를 확인한다. 경로는 요청 → `wiki-path` → `WIKI_PATH` → 사용자에게 확인한 값 순이며 상대 경로는 프로젝트 루트 기준이다.
3. 위키 위치·최상위 분류·추가 하위 구조·기존 문서 유지/이관 범위·인덱스 정책에서 미정인 사항을 한 번에 확인한다. 이미 사용자가 정한 값은 다시 묻지 않는다. 기존 설정 변경은 사용자 지시나 확인을 근거로 한다.
4. 미정이면 `./wiki`와 `concepts`(개념)·`decisions`(ADR)·`references`(외부 자료), 모든 디렉토리에 `index.md`를 두는 기본안을 제안한다. 자주 함께 읽는 문서를 묶되 불필요한 하위 구조를 미리 만들지 않는다.

## 파일 생성

형식은 OKF v0.1 스타일의 Markdown + YAML frontmatter를 사용한다. 파일을 만들 때 [초기 파일 형식](references/initial-files.md)을 읽고 선택한 경로·분류·정책에 맞게 조정한다.

- 프로젝트 `.agents/wiki-path`에는 경로만 기록한다. 주석·비밀 값은 넣지 않는다.
- `.agents/wiki-structure.md`에는 위키 경로·형식·인덱스 정책·분류 지도·로그 위치·운영 규칙을 기록한다. 이 파일은 프로젝트 설정이다.
- 위키 루트와 선택한 분류, `logs/`를 만들고 합의한 정책에 따라 `index.md`를 둔다. 기본 정책은 깊은 하위 디렉토리에도 적용한다.
- 각 인덱스는 자기 범위와 바로 아래 문서·하위 디렉토리 인덱스만 안내한다. 전체 문서를 한 인덱스에 나열하지 않는다.
- `logs/index.md`는 바로 아래 로그를 최신순으로 안내한다. 로그는 `YYYY-MM-DD-kebab-case.md`로 만들고 실제 현재 날짜와 구조 생성·변경 이유·영향을 기록한다.
- 문서는 한 주제를 다루고 새 문서·디렉토리는 해당 인덱스에 등록한다. `decisions/`는 번호가 있는 ADR로 관리한다.

## 보존과 완료

- 기존 인덱스를 덮어쓰지 않는다. 누락된 인덱스를 추가할 때도 기존 문서·링크를 먼저 읽어 보존한다.
- 프로젝트 파일·기존 위키 문서를 삭제하거나 자동 이동하지 않는다. 루트 `log.md`도 보존하며 필요하면 `logs/index.md`에서 레거시 기록으로 안내한다.
- 생성·변경한 파일과 구조·링크가 합의한 설정에 맞는지 확인하고 결과를 보고한다. 이후 사용할 `$wiki-update`·`$wiki-read`를 안내한다.
